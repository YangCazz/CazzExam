# CazzExam Next：产品与架构设计基线

日期：2026-11-20 ｜状态：设计基线，尚未实现或验收。

## 1. 产品定位

CazzExam Next 是可以从一个问题出发、顺着概念联系学下去的备考知识工作台。考试是观察同一知识体系的视角，不是首页的任务清单。保留多种高级资格，第一批只优先验证系统架构设计师的内容，不替用户选择考试。

参考已确认的现代蓝紫方向与 Web／手机设计板；不是给旧版学习总览换皮。首页不设每日任务、打卡、倒计时、强制诊断。练习、模拟和考务信息由用户主动进入。保留旧版独立可用，不改写旧学习记录。

## 2. 第一条可用流程

| 步骤 | Web | 手机 |
| --- | --- | --- |
| 探索 | 主栏提供自然语言搜索和精选主题；考试视角是可切换筛选，默认允许看全部；不出现任务统计 | 单列首页，搜索和所选视角位于上方；底栏只放探索、地图、收藏 |
| 概念阅读 | 阅读主栏给简明解释、例子和取舍；窄侧栏放考纲映射和关联概念 | 阅读优先；关联和考试出处按段落内卡片或展开区呈现，不必在手机上横向操作图谱 |
| 继续探索 | 展示关联方向及其理由，例如“服务拆分 → 事务一致性：拆分会跨越事务边界”；支持返回原搜索和选中位置 | 同样能进入关联节点、回退原位置；不依赖悬停、拖拽或精细手势 |

视觉用清晰的中文文字层级、高可读中性色与低饱和蓝紫强调色；状态除颜色外必须有文字。令牌统一控制色彩、间距、圆角、动效，桌面与移动端复用组件，不另做套皮。验证键盘可达、焦点可见、无障碍对比、减少动效、窄屏换行。首批必须覆盖空搜索、无结果、加载、读取失败、直接打开概念链接与返回；无结果允许改词或取消考试筛选。暂不承诺原生 App。

## 3. 技术方案：独立新版、模块化单体

先复用团队熟悉的 Vue + TypeScript + Vite 和 FastAPI 的技术栈，不继承旧版任务首页、路由或数据库契约。在独立 `next/web` 与 `next/api` 验证，仓库内旧 `frontend`、`backend`、数据和启动方式保持原状。先用一种部署单元、可迁移的 SQLite，首批从人工可审阅的版本化原创内容种子导入，不先上微服务、向量数据库、双端原生或复杂同步。改数据库和新增服务必须有明确的使用负载或协作需求。

- **知识域**：Concept 使用稳定 ID；显示标题、别名、段落、可溯源版本。ConceptRelation 记录方向、关系类型、解释，跨考试复用，不以章节号做主键。
- **考试域**：Qualification、SyllabusVersion、SyllabusMapping 分开管理。映射记录来源、考纲版本和证据状态；原文、本站解释和可靠程度清楚区分。趋势只显示样本场次、可核来源和缺失说明。首批不生成趋势排行榜。
- **题库域**：Paper、Question、SourceRecord、ReviewStatus 与权利字段独立。题面可信度与使用权分别判定；未核、缺件、冲突、权利不明不计分。首批可用原创样例测试；不复制外站题文、解析或图片。现有核验分支独立继续，不把量当成质量。
- **个人空间**：标注、笔记、收藏未来单独存放；不把私人数据放进公共知识包。本切片不接账号与跨设备同步；未实现的功能不显示误导性成功。收藏底栏可在持久化准备好后上线。
- **API 边界**：候选 `GET /api/v1/concepts?q=&qualification=`、`GET /api/v1/concepts/{slug}`、`GET /api/v1/qualifications`。ID 稳定、slug 可做重定向。搜索先做标题、别名和中文词片匹配，能解释排序结果；无相关证据不靠模型补题。明确区分空结果、加载失败和无考纲映射。

## 4. 实现顺序与验收

1. 独立新版能本地启动，用少量原创概念走通探索、搜索、阅读、继续探索；给出内容版本和提交 SHA。前端是否需要后端与本地启动命令必须写清，不能用静态展示冒充联调。
2. 桌面与手机视口各验收同一条主路径，另测窄屏、键盘、前进后退、无结果、读取失败。验证同一概念能因不同资格出现不同考纲映射而不被重复复制。测试报结果，不以“有设计稿”代替跑通。
3. 架构师题源进来时，先验来源映射、隔离待核题和拒绝缺件计分，再选自由练习；别为等齐整卷阻塞探索版。旧版数据迁移另做可回退方案。
4. 每完成一块，做可审阅的小提交并读回 GitHub。此设计提交只保存产品／架构／交互基线，不改 master、题库分支或部署。代码、运行验证和上线各自明确报告。
