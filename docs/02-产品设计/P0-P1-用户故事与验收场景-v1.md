## 1. 使用说明

- 优先级：P0 为内容与诊断基础；P1 为每日闭环。两者共同构成首个可用版本。
- 格式：用户故事描述用户价值；验收场景采用 Given / When / Then，可直接转化为测试用例。
- 不在本文决定数据表、接口或算法细节；这些内容进入后续 SRS 和技术设计。

## 2. P0：个人设置与首次诊断

### US-P0-01 设置目标与约束

作为备考者，我希望设置资格、考试日期、每周可用时间和个人基础，以便系统给出适合我的学习节奏，而不是固定的倒计时计划。

**验收场景**

```text
场景：完成基础设置
Given 我第一次使用且没有个人设置
When 我填写系统架构设计师、目标日期与每周可用时间并保存
Then 系统保存这些设置并显示可编辑的学习节奏建议
And 不在任何页面继续显示硬编码的考试日期

场景：未填写考试日期
Given 我完成其他设置但未选择考试日期
When 我进入学习总览
Then 系统提示设置目标批次可获得冲刺节奏
And 仍允许我开始诊断和日常练习

场景：修改可用时间
Given 我已有已生成但未开始的未来任务
When 我将每周可用时间从 8 小时改为 4 小时
Then 系统提示计划需要重排
And 已完成及进行中的任务不被删除
```

### US-P0-02 完成可中断的首次诊断

作为首次使用者，我希望通过短诊断了解三科起点，并能在工作中被打断后继续，以便不会因一次完整考试压力而放弃。

**验收场景**

```text
场景：完成三部分诊断
Given 我尚无有效历史学习数据
When 我完成综合短题组、一个案例小问和论文提纲/素材盘点
Then 系统生成一份三科独立的诊断报告
And 报告包含数据可信度和第一周建议

场景：诊断中断后继续
Given 我已完成综合诊断的一部分题目
When 我主动暂存或关闭页面后再次进入诊断
Then 我可以从上次未完成位置继续
And 已作答内容、用时和置信度不丢失

场景：跳过论文诊断
Given 我没有可立即填写的项目经历
When 我选择跳过论文部分并说明“暂无素材”
Then 报告将论文标为“数据不足/需建立素材”
And 不将论文判为低能力或给出虚假分数
```

### US-P0-03 理解诊断结果

作为备考者，我希望看懂报告结论的依据，以便相信并采纳第一周计划。

**验收场景**

```text
场景：展示高风险证据
Given 综合知识诊断正确率低且多题超时
When 我查看综合知识风险卡
Then 我能看到“正确率”“用时”“覆盖度”等支持结论的证据
And 我能直接进入一项对应训练

场景：数据不足
Given 某一科只有极少量有效作答
When 系统生成诊断报告
Then 该科显示“数据不足”而非安全/临界/高风险
And 系统说明需要完成什么训练以获得更可靠判断
```

## 3. P1：今日任务与日常闭环

### US-P1-01 查看并开始今日任务

作为稳定学习中的备考者，我希望在首页看到少量、明确且可直接开始的任务，以便在有限时间内马上进入有效学习。

**验收场景**

```text
场景：生成任务包
Given 我已完成诊断或已有足够历史学习数据
And 今天可用时间为 35 分钟
When 我进入学习总览
Then 我看到 1 至 3 个任务，预计总时长不超过 35 分钟
And 每个任务展示预计时长、完成条件和推荐原因

场景：一键开始
Given 今日任务中有“综合练习：性能与可用性”
When 我点击“开始练习”
Then 我在两次操作内进入已按任务配置好的题组
And 无须重新选择知识点、题量或模式

场景：任务数据不足
Given 某薄弱主题没有已发布的关联题目
When 系统尝试生成该主题的训练任务
Then 系统不以无关题目替代
And 显示内容缺口及导入/审核入口
```

### US-P1-02 动态调整当天时间

作为在职备考者，我希望根据临时空闲时间重排任务，以便计划适应生活而不是制造挫败。

**验收场景**

```text
场景：减少时间预算
Given 我有一个 60 分钟的任务包且尚未开始任何任务
When 我把今天可用时间改为 15 分钟
Then 系统保留到期复习并移出低优先级任务
And 显示被推迟的任务及原因

场景：正在进行中的任务
Given 我已经开始一个 15 分钟综合练习
When 我调整当天可用时间
Then 已开始任务保持不变
And 仅重排未开始任务
```

### US-P1-03 跳过与延期

作为备考者，我希望无法完成任务时能说明原因并安全地重排，以便学习记录真实反映我的状态。

**验收场景**

```text
场景：跳过任务
Given 我有一项未开始任务
When 我选择跳过并标注“时间不足”
Then 任务状态变为已跳过并保留原因
And 系统不因本次跳过降低我的掌握度

场景：到期复习延期
Given 今天有一项到期错题复习
When 我选择延期到明天
Then 系统记录延期行为并将其作为明天的高优任务候选
And 不静默删除该复习任务
```

### US-P1-04 完成任务并获得反馈

作为备考者，我希望在训练结束后知道结果会怎样影响后续计划，以便理解努力的价值。

**验收场景**

```text
场景：完成综合任务
Given 我通过今日任务进入一组综合题
When 我完成并提交题组
Then 任务显示已完成
And 结果页显示正确性、用时、错题和下一步建议
And 我的学习记录、能力证据和后续推荐被更新

场景：任务未达完成条件
Given 一个案例任务要求完成一个小问并写复盘
When 我只输入了答案但未提交或暂存
Then 任务保持进行中或暂存
And 系统不将其计为已完成
```

## 4. P1：三类训练与复盘

### US-P1-05 综合知识练习与置信度

作为备考者，我希望记录自己做题时的把握程度，以便识别“蒙对”和“自信却错”的盲区。

**验收场景**

```text
场景：提交单选后反馈
Given 我正在完成综合题组
When 我为每题作答并选择置信度后提交
Then 我能查看答案、解析、用时与关联知识点
And 系统标记高置信错误和低置信正确等偏差

场景：未填写置信度
Given 我未选择某题的置信度
When 我提交题组
Then 系统允许提交并将该题置信度记为未知
And 不把未知当作低置信或高置信
```

### US-P1-06 案例小问自评

作为备考者，我希望先独立作答再核对评分点，以便练习真实的案例得分能力而不是阅读答案。

**验收场景**

```text
场景：先答后看评分点
Given 我开始一个案例小问任务
When 我保存并提交自己的答案
Then 系统才开放参考评分点和参考答案
And 我可以逐项标记已覆盖、待补充、不适用或待确认

场景：补充后保存复盘
Given 我已对照评分点发现遗漏
When 我补写答案并填写复盘
Then 系统保存初始答案、补充内容和遗漏评分点
And 后续建议可针对遗漏能力单元生成
```

### US-P1-07 论文素材与提纲

作为备考者，我希望先积累真实项目事实并形成提纲，以便论文练习不会只依赖空泛模板。

**验收场景**

```text
场景：创建项目事实卡
Given 我有一个真实项目经历
When 我填写背景、职责、约束、决策和结果
Then 系统保存事实卡并允许关联论文主题和质量属性
And 该事实卡可以在后续论文提纲中被检索

场景：完成提纲训练
Given 我选择一篇论文题目并使用事实卡建立提纲
When 我保存提纲但未进行全文写作
Then 系统将该任务记录为“论文提纲训练已完成”
And 不将其误计为完整论文模拟
```

### US-P1-08 错题归因与间隔复习

作为备考者，我希望错题能按原因进入复习队列，以便解决根因而不只是反复看答案。

**验收场景**

```text
场景：错题进入复盘
Given 我提交综合题并答错一题
When 我查看结果页
Then 我可以选择错因并填写最小反思
And 保存后该题进入复习队列或提示待补充归因

场景：复习时先回忆
Given 一道错题今天到期复习
When 我开始复习
Then 系统先显示题干和我的历史反思，不直接显示答案
And 我重新作答或表述后才能查看反馈

场景：连续复习失败
Given 我已连续两次未正确完成同一主题的复习
When 我再次提交失败
Then 系统推荐回到相关知识点或案例评分点
And 不只将同一道题以更短间隔重复推送
```

## 5. P1：风险与周回顾

### US-P1-09 查看三科独立风险

作为备考者，我希望分别看到三科的风险与证据，以便及时纠正偏科。

**验收场景**

```text
场景：一科高风险
Given 综合、案例、论文中至少一科的近期证据显示明显薄弱
When 我查看学习总览或周回顾
Then 系统分别显示三科状态，不用平均值掩盖高风险科目
And 高风险科目提供一项明确的下一步任务

场景：没有近期模拟
Given 我尚未完成任何完整模拟
When 系统展示风险证据
Then 最近模拟项显示“尚无数据”
And 不将其视为 0 分或负面证据
```

### US-P1-10 完成周回顾并重排下周

作为备考者，我希望每周总结投入和结果，并按真实时间重新安排下一周，以便计划保持可执行。

**验收场景**

```text
场景：生成周回顾
Given 我本周有训练、复习或跳过记录
When 我进入周回顾
Then 系统展示投入时间、任务完成、三科变化和主要证据
And 输出不超过三条下周行动建议

场景：下周时间减少
Given 系统已生成下周建议
When 我将下周可用时间降低
Then 系统优先保留到期复习与高风险科目任务
And 显示哪些任务被降级或延后
```

## 6. P0：内容质量与导入审核

### US-P0-04 导入并审核个人资料

作为题库维护者（即个人用户），我希望导入材料先经过校验和审核，再参与训练，以便能力评估不会被错误内容污染。

**验收场景**

```text
场景：导入字段不完整
Given 我导入一条单选题但缺少答案或大纲标签
When 系统校验导入内容
Then 该题进入暂存/待补充状态
And 系统指出缺少字段
And 该题不参与诊断、模拟或能力计算

场景：发布审核题目
Given 一道题具备题干、答案、来源、题型、科目和大纲标签
When 我确认发布
Then 该题进入正式训练库
And 后续任务和统计可以使用它

场景：标记争议题
Given 我发现已发布题目的答案存在争议
When 我将其标记为待核
Then 该题从核心评估中排除
And 历史作答记录保留且被标记为受影响
```

## 7. 跨故事验收与度量事件

所有 P0/P1 流程需满足：

1. 用户在任务/训练中刷新、关闭或返回时，已明确保存的内容不丢失。
2. 任一系统推荐均可追溯到用户数据或明确规则；不可出现无理由的任务。
3. 所有时间相关显示使用用户所在时区的本地日期。
4. AI 不可用、题库为空、网络/本地后端不可用时，界面提供可理解的降级反馈。
5. 不将学习数据上传到外部服务，除非用户对对应 AI 操作明确授权。

建议记录的产品事件（用于本地统计与后续评估）：

| 事件 | 关键属性 |
| --- | --- |
| `diagnostic_started/completed/paused` | 科目、完成度、用时 |
| `task_generated/started/completed/skipped` | 类型、原因、预计/实际用时、生成理由 |
| `practice_submitted` | 题型、题量、正确性、置信度、用时 |
| `reflection_saved` | 错因、是否填写反思 |
| `review_completed` | 回忆结果、复习次数、下次计划 |
| `weekly_review_completed` | 本周投入、下周时间预算、三科状态 |
| `content_published/flagged` | 内容类型、来源、审核状态 |

## 8. 进入软件需求前的确认点

在编写 SRS 前，需要确认以下产品取舍：

1. 首次诊断的具体题量和最长时长；
2. 今日任务默认时间档（15/30/60/120 分钟是否合适）；
3. 论文首期是“事实卡 + 提纲”还是包含完整限时写作；
4. 用户是否接受对任务跳过原因进行最小记录；
5. 题库审核是否由用户自己操作，还是先保留简单发布状态；
6. 三科风险的初版判定阈值由规则配置还是仅展示证据。
