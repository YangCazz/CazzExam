## 1. 创意方向：深夜书桌上的架构工作台

视觉关键词：**沉静、理性、可信、专注、可持续**。

产品不应像娱乐化刷题 App，也不应像强调营销的通用 SaaS。它更接近“架构师的个人控制台”：深色背景降低长时间阅读疲劳，稀疏而明确的色彩表达行动优先级，信息排版有技术文档的秩序感。

核心情绪是“我知道今天只要完成这几步”，而不是“我还有大量任务没有做”。

### 应避免的风格

- 高饱和霓虹、游戏化等级/金币/连续打卡压迫；
- 大面积玻璃拟态、过度渐变、悬浮特效；
- 无实际意义的大数字 KPI 墙；
- 论文/案例页面使用花哨插画，干扰阅读与写作；
- 红绿颜色单独表达状态，或以红色制造焦虑。

## 2. 视觉参考结论

已生成的桌面概念图验证了方向：左侧为稳定工作台导航，中间用三张“行动任务”承载今天的主线，右侧以紧凑的三科风险作为纠偏信息，底部用周回顾承接长期反馈。

概念图仅用于确认气质与信息层级，不直接作为前端截图或像素级实现依据。实现须以线框、交互状态与设计令牌为准。

## 3. 色彩系统

### 3.1 基础色板

现有前端的深色基调适合保留；建议将现有 token 进一步语义化。

| 语义 | 建议值 | 用途 |
| --- | --- | --- |
| Ink 950 | `#080C16` | 页面主背景 |
| Ink 900 | `#0C1220` | 次级背景、侧栏 |
| Ink 800 | `#121A2C` | 实色面板、输入区域 |
| Slate 400 | `#8B9AB9` | 次要文字 |
| Paper 50 | `#E7EDF8` | 主文字 |
| Blue 500 | `#5B8CFF` | 主操作、链接、当前导航 |
| Violet 500 | `#9B6CFF` | 辅助强调、案例主题 |
| Jade 400 | `#34D399` | 完成、稳定、正向反馈 |
| Amber 400 | `#FBBF24` | 到期、提醒、临界风险 |
| Coral 400 | `#F87171` | 高风险、保存失败、破坏性操作 |

### 3.2 颜色使用比例

- 80–85%：深色中性背景、面板和正文；
- 10–15%：蓝/紫，用于导航、主操作和当前学习焦点；
- 少于 5%：玉绿/琥珀/珊瑚，只作为状态和任务类型提示。

同一界面同时出现的强调色不超过三种。状态必须始终搭配文字，例如“高风险”“已完成”“今天到期”。

### 3.3 语义映射

| 语义 | 色彩 | 示例 |
| --- | --- | --- |
| 主行动 | 蓝 | 开始今日任务、确认计划 |
| 案例/分析 | 紫 | 案例小问标签、评分点进度 |
| 已完成/稳定 | 玉绿 | 已完成任务、稳定能力证据 |
| 提醒/临界 | 琥珀 | 到期复习、需要关注的用时 |
| 风险/失败 | 珊瑚 | 保存失败、单科高风险 |
| 中性信息 | Slate | 数据不足、次要说明、历史记录 |

## 4. 字体与排版

### 4.1 字体

沿用兼容 Windows 的字体栈：`Segoe UI`、`Microsoft YaHei`、`PingFang SC`、`Helvetica Neue`、Arial。代码、时间、题号、分值使用 `Cascadia Code` / Consolas 等等宽字体。

不引入依赖网络加载的花体。中文内容可读性优先于“科技感”。

### 4.2 类型层级

| 层级 | 建议尺寸 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 24–28 px | 650–700 | 今天先做什么、首次诊断 |
| 区块标题 | 16–18 px | 600–700 | 三科风险、本周回顾 |
| 任务标题 | 16 px | 600 | ATAM 架构评估、案例小问 |
| 正文 | 14 px | 400 | 题干、说明、复盘 |
| 辅助文本 | 12–13 px | 400–500 | 推荐理由、保存时间、标签 |
| 数据/计时 | 13–16 px | 500–600 | 用时、题号、分值 |

长题干和论文正文建议 16 px、1.75–1.9 行高，正文最大行宽 720–800 px；避免在超宽屏将文本拉满。

## 5. 布局、间距与层级

### 5.1 桌面布局

- 侧栏：240–256 px，始终承载导航与当前资格；
- 主内容最大宽度：1440 px，左右留白 28–40 px；
- 今日任务为主栏，三科风险为次栏；窄于 1100 px 时风险下移；
- 题目与作答区使用 45/55 或 40/60 分栏；窄屏纵向排列；
- 页面顶部只保留标题、简短上下文和一个主操作，避免常驻大横幅。

### 5.2 间距节奏

采用 4 px 基础单位：4 / 8 / 12 / 16 / 24 / 32 / 48。

- 卡片内部：16–20 px；
- 任务卡之间：12 px；
- 页面区块之间：24 px；
- 长文本段落：12–16 px；
- 高优先级任务左侧使用 3–4 px 状态色条，而非整卡填色。

## 6. 组件视觉语言

### 6.1 任务卡

任务卡是产品最重要的视觉单元，包含：任务序号/类型、标题、预计时间、推荐理由、完成条件和一个明确操作。

- 高优任务：左侧琥珀细条，主操作为蓝色实心按钮；
- 案例任务：紫色细条和紫色文字标签，不使用大面积紫色背景；
- 论文素材：玉绿细条；
- 已完成：降低整体对比度，保留绿色文字“已完成”，不要把卡片隐藏；
- 已跳过/延期：中性色展示原因，不使用失败红色。

### 6.2 风险卡

风险卡应紧凑、证据优先：科目名 → 状态文字 → 一行证据 → 一项行动。

禁止只展示“大分数”和仪表盘。数据不足使用中性灰和明确说明，不暗示负面表现。

### 6.3 训练工作台

- 题干区域是阅读面，不加复杂装饰；
- 作答区使用更实的 Ink 800 背景，使输入焦点清晰；
- 计时器、题号、保存状态固定在顶部上下文条；
- 案例评分点与参考答案以可展开层级出现，提交前不可见；
- 正确/错误反馈应紧随对应题目，不在一长串结果顶部汇总后让用户寻找。

### 6.4 复盘和周回顾

- 复盘输入优先：错因选择和一句反思比图表更靠前；
- 周回顾强调“本周变化”和“三项下周行动”，其余统计折叠或降级；
- 图表只在能解释趋势时使用，避免为了装饰而加雷达图、环形图。

## 7. 图标与插画

- 使用统一的 1.75–2 px 线性图标（现有 `Icon.vue` 可继续扩展）；
- 图标用于扫描与定位，不用于代替文字标签；
- 首期不需要人物插画、背景插画或装饰性照片；
- 空状态可用简洁的线性图形（待诊断、无题目、已完成），但应由 SVG/前端代码实现，保持轻量和可控；
- 知识图谱、时间趋势、覆盖热图采用数据可视化，不采用 AI 生成信息图。

## 8. 动效与反馈

动效只帮助理解状态变化：

- 任务完成：150–200 ms 的淡入/收束，随后显示下一步；
- 保存状态：文字与图标变更，不使用持续转圈；
- 风险变化：在周回顾中以向上/向下文字趋势配合简短过渡；
- 页面切换：短淡入，不使用大幅滑入；
- 尊重系统“减少动态效果”偏好。

禁止连续闪烁、自动轮播、积分爆炸式庆祝和倒计时焦虑动画。

## 9. 可访问性与亮色模式预留

- 正文与背景至少达到 WCAG AA 可读性；
- 状态传达同时使用文字、图标/形状与颜色；
- 键盘焦点使用清晰蓝色描边，不能仅靠 hover；
- 亮色模式不在 P0/P1 实现，但 token 必须按语义命名，禁止直接在业务组件写深色十六进制；
- 图表的系列色必须在深/浅两套主题下都可辨识。

## 10. 现有前端的对齐建议

现有 `frontend/src/style.css` 已有深色背景、蓝紫主色、绿/黄/红状态色和 Microsoft YaHei 字体栈，能够作为本方案的基础。

后续实现建议：

1. 将 `--accent`、`--ok` 等现有 token 补齐为语义 token（`--action-primary`、`--status-success`、`--risk-high` 等），再由语义 token 引用原始色板；
2. 弱化大面积渐变在普通卡片和导航上的使用，仅保留给主操作/当前焦点；
3. 将首页现有统计卡网格替换为“今日任务主线 + 三科风险侧栏 + 周回顾”；
4. 在任务、训练和表单中增加清晰的保存、进行中、已完成与异常状态；
5. 以样式 token 和可复用组件实现上述规则，不将颜色/间距散落在各个 View 内。

## 11. 实现前的视觉验收

1. 用户在首屏一眼可找到唯一主操作“开始今天的主任务”。
2. 同时存在多种状态时，用户无需阅读图例也能区分任务类型、完成与风险。
3. 长题干、案例材料和论文编辑连续阅读 20 分钟不产生明显视觉负担。
4. 1280 px 桌面和 390 px 窄屏都能完整完成“开始任务—暂存—提交—复盘”。
5. 无 AI、无数据、保存失败、内容待核等状态与正常状态同样有明确、克制的界面表现。
