## 1. 问题定义

系统架构设计师备考不是单一的刷题任务：综合知识考广度与速度，案例分析考知识迁移和按评分点作答，论文考项目事实、结构化表达与限时输出。三科需在同一次考试中协同达标，单纯按照章节刷题或只看累计正确率，会产生三个典型问题：

1. 不知道今天最值得做什么，计划容易被“看起来努力”的低收益任务取代；
2. 只知道题错了，不知道是知识、审题、方法、时间还是表达出了问题；
3. 只练单选或只积累论文模板，无法发现三科之间的偏科风险。

现有题库类产品通常提供题目和答案，却不保存用户的学习资产（错因、反思、项目事实、能力变化），也不能为个人的剩余备考时间重排优先级。

## 2. 产品愿景与定位

### 2.1 愿景

让备考者每天明确完成最有价值的一步，并在考试前形成可以解释、可以复盘、可以迁移的能力与素材资产。

### 2.2 定位

不是一个仅提供题目的在线题库，而是一个**本地优先、自适应、三科协同**的备考工作台。

### 2.3 北极星结果

用户在任意一天打开产品后，能在 30 秒内理解：

- 当前距离三科同时达标还有多大风险；
- 今天应该完成哪 1–3 个任务，以及为什么；
- 完成任务后，哪些能力和后续计划发生了变化。

## 3. 目标、非目标与成功标准

### 3.1 产品目标

1. 建立从诊断、计划、训练、复盘到复习的日常学习闭环。
2. 让综合知识、案例分析与论文的风险可分别看见、可分别改善。
3. 将用户的错因、反思、项目经历和架构决策保存为可复用的个人资产。
4. 让资格、科目、大纲和考试模板可配置，为其他软考资格复用学习引擎。

### 3.2 非目标（v1 不做）

- 不提供社交、排行榜、讨论区或课程直播。
- 不在首期构建账号、支付、云端同步或多人协作；本地数据优先。
- 不让 AI 自动认定案例/论文的最终分数，AI 结果只能作为建议。
- 不以爬取、公开分发受版权保护的真题材料为产品能力。
- 不一次性支持所有软考资格；先将资格配置抽象好，首期只验证架构师。

### 3.3 成功标准（上线后观测）

| 层级 | 指标 | v1 目标 |
| --- | --- | --- |
| 激活 | 用户完成首次诊断并生成第一周计划 | 单用户流程 100% 可完成 |
| 日常闭环 | 已生成的当日任务中，至少完成一个任务的天数占学习日比例 | ≥ 70% |
| 复盘质量 | 错题中具备错因或反思的比例 | ≥ 85% |
| 三科均衡 | 周回顾可输出三科独立风险和至少一条行动建议 | 100% 覆盖 |
| 内容质量 | 已发布题目具备来源、题型和至少一个大纲标签的比例 | 100% |
| 数据安全 | 用户能完成备份与恢复演练 | 100% 可验证 |

“是否通过考试”是终极结果，但受备考投入、题库规模与考试变化影响，不可作为首期唯一验收指标。

## 4. 目标用户与场景

### 4.1 核心用户：在职备考者

| 维度 | 假设 |
| --- | --- |
| 背景 | 有研发、架构、测试、运维或项目经验；理论体系不完整 |
| 时间 | 工作日碎片时间 + 周末集中学习，备考周期约 8–24 周 |
| 目标 | 高级资格当次三科一起通过；需要可控、可持续的节奏 |
| 行为 | 手中已有 PDF/Excel 真题、笔记与项目经历，但资料分散 |
| 顾虑 | 不想把真题、论文素材和 API 密钥交给不透明的在线服务 |

### 4.2 次要用户：跨资格备考者

在系统架构设计师之后，准备系统分析师、软件设计师、网络规划设计师等软考资格的用户。其学习方法可复用，但科目、大纲、题型和评分规则不同。

### 4.3 关键场景

| 场景 | 用户目标 | 产品应提供的结果 |
| --- | --- | --- |
| 第一次使用 | 判断基础与差距，避免盲目开刷 | 三科诊断、风险说明、第一周任务 |
| 工作日 30 分钟 | 快速完成一个高收益任务 | 可直接开始的短任务包与完成条件 |
| 周末 2–3 小时 | 练习考试节奏和综合输出 | 分科限时训练或模拟、报告与复盘 |
| 做错/不确定 | 将一道错题转化为长期能力 | 错因、正确思路、复习时间、关联知识点 |
| 写论文前 | 从真实项目经验中快速取材 | 可检索的项目事实卡与提纲检查 |
| 考前冲刺 | 避免偏科和遗漏 | 三科风险、到期复习、模拟与时间建议 |
| 导入资料 | 将个人题库转化为可训练内容 | 校验、来源记录、标签和审核状态 |

## 5. 用户任务与产品闭环

### 5.1 主闭环

```text
首次诊断 / 历史学习数据
        ↓
能力与风险评估
        ↓
今日任务（复习优先 + 薄弱高频 + 三科平衡）
        ↓
练习、案例拆解、论文练笔或模拟
        ↓
作答结果 + 用时 + 置信度 + 错因 + 反思
        ↓
掌握度、复习队列和后续任务更新
```

### 5.2 三条必须打通的用户路径

**路径 A：从“不会”到“稳定掌握”**

诊断发现薄弱知识点 → 短练习 → 错因/反思 → 间隔复习 → 多次正确且稳定 → 能力状态升级。

**路径 B：从“知识”到“案例得分”**

知识点学习 → 案例小问限时回答 → 对照评分点自评 → 补全表达与方法 → 同类案例再练。

**路径 C：从“项目经历”到“论文输出”**

记录项目事实 → 关联架构主题与质量属性 → 选择论文题 → 生成提纲 → 限时写作 → 结构与事实复盘 → 素材补充。

| PR-02 | 首次诊断：综合小题、案例小问、论文提纲 | M | 明确起点与偏科 | 能生成三科风险和第一周建议 |

## 7. 核心业务规则（产品口径）

1. **三科独立判定**：任何总体分数都不能替代分科风险；一科高风险即总目标高风险。
2. **到期复习优先**：当日有到期复习时，任务包必须优先包含；用户可延期，但系统记录原因。
3. **推荐必须可解释**：每个任务必须显示至少一个推荐理由，例如低掌握度、即将遗忘、高频知识点或分科失衡。
4. **错题不是唯一的复习来源**：高置信错误、长时间未练、模拟中耗时异常和案例评分点缺失，也可进入复习/训练建议。
5. **能力更新基于证据**：正误、难度、用时、置信度、重复间隔和人工评分共同影响能力，不能仅依赖一次正确率。
6. **AI 不替代用户判断**：AI 生成的评分、归因、标签须标识来源，并允许确认、修改或拒绝。
7. **未审核题不影响核心评估**：待核、答案存在争议或标签不完整的题目，不进入正式诊断、模拟和能力计算。
8. **个人资料最小外发**：未明确授权时，项目经历、论文正文和题目内容不发送到外部 AI 服务。

## 8. 信息架构（产品层）

```text
学习总览
├─ 今日任务
├─ 三科风险与近期变化
└─ 周回顾

学习与训练
├─ 诊断
├─ 知识地图
├─ 题组练习
├─ 案例工作台
├─ 论文工作台
└─ 模拟考试

复盘与资产
├─ 错题与复习队列
├─ 能力画像
├─ 项目事实卡 / ADR
└─ 学习记录

内容与设置
├─ 题库与导入审核
├─ 资格 / 大纲 / 考试配置
├─ 数据备份与导出
└─ AI 与隐私设置
```

## 9. 关键体验要求

### 9.1 今日任务

- 每天的默认任务数量为 1–3 个，可按可用时间调整；
- 一键开始，无须先穿过多层筛选页面；
- 每项任务给出预计分钟、完成条件、优先级和推荐原因；
- 完成后显示“本次学习影响”：完成量、错题变化、下一次复习或建议；
- 用户可以跳过，但须选择原因（时间不足/内容不熟/其他），避免系统误判。

### 9.2 训练反馈

- 选择题在提交后展示正确性、解析、关联知识点和置信度偏差；
- 案例题先让用户自评/补充，再展示评分点，降低“看答案觉得都会”的错觉；
- 论文写作强调真实项目事实和结构完整性，不鼓励模板化编造；
- 任意训练都允许保存中途进度，避免工作日被打断后损失内容。

### 9.3 风险表达

- 风险用“安全 / 临界 / 高风险”而非单一总分；
- 风险说明同时展示证据（覆盖度、准确率、用时、遗忘、最近模拟）；
- 数据不足时明确提示“尚无足够证据”，不能伪造精确预测。

## 10. 内容需求与质量标准

题目或材料进入正式训练库前，至少具备：

| 内容类型 | 必填内容 |
| --- | --- |
| 单选 | 题干、选项、答案、解析、题型、科目、来源、至少一个大纲标签 |
| 案例 | 材料、每个小问、分值/目标用时、参考评分点、科目、来源、标签 |
| 论文 | 题目、年份/场次、建议提纲或评分维度、关联主题、来源 |
| 项目事实卡 | 真实背景、本人职责、约束、决策、结果/证据、可用主题 |

所有内容应具有状态：`暂存`、`待审核`、`已发布`、`待核/有争议`、`归档`。只有已发布内容参与核心学习计算。

## 11. 约束与风险

| 风险 | 影响 | 产品应对 |
| --- | --- | --- |
| 真题版权与来源不清 | 内容不可用或质量不可信 | 仅个人导入；记录来源与审核状态 |
| 题库规模不足 | 风险判断失真、训练重复 | 优先建设导入审核与覆盖度提示 |
| 考试规则变化 | 模拟和计划失效 | 资格/考试模板配置化；日期不硬编码 |
| AI 评分幻觉 | 用户被错误反馈误导 | 人工确认、结果可编辑、评分点优先 |
| 备考时间波动 | 固定计划无法执行 | 基于可用时间生成任务，允许跳过和重排 |
| 本地数据丢失 | 用户资产不可恢复 | 可见的备份、导出与恢复演练 |

## 12. 需要用户确认的决策

以下信息会影响第一版 PRD 的范围与指标，当前按“个人本地备考、8–24 周周期”的保守假设编写：

1. 预计参加的具体考试批次和所在地；
2. 每周可稳定投入的时间、工作日/周末的时间结构；
3. 当前基础：是否已有软考经历、综合/案例/论文的自我评估；
4. 已拥有资料的类型、年份范围和整理程度；
5. 是否有可用于论文的真实项目经历，以及隐私边界；
6. 本地单机是否为长期约束，还是未来需要跨设备同步。
