## 1. 目的与范围

本说明定义“系统架构设计师备考工作台”P0/P1 的软件行为，以支持后续架构、数据库、接口、前端页面和测试的设计。

系统为单用户、本地优先 Web 应用。首期仅支持一个默认资格（系统架构设计师），但所有资格、科目和考试日期均不得在业务逻辑中硬编码。

### 1.1 范围内能力

1. 个人目标与学习时间设置；
2. 可暂存的三科首次诊断与诊断报告；
3. 每日学习任务的生成、重排、开始、暂存、完成、跳过和过期处理；
4. 综合题组、案例小问、论文事实卡/提纲和错题复习；
5. 作答结果、错因、反思、复习计划和能力证据记录；
6. 三科风险摘要与周回顾；
7. 题目/材料的暂存、待审核、发布、待核和归档状态；
8. 本地备份、导出和 AI 降级提示。

### 1.2 范围外能力

- 多账号、权限协作、在线支付、社群、课程商城；
- 云同步与跨设备实时协作；
- AI 自动决定最终得分或自动发布题目；
- 其他资格的完整内容与页面；
- 真题采集、爬取与公开分发。

## 2. 术语与角色

| 术语 | 定义 |
| --- | --- |
| 用户 | 本地应用的唯一学习者，也是内容维护者 |
| 资格 | 一项软考资格，例如系统架构设计师 |
| 科目 | 资格下的考试科目：综合知识、案例分析、论文 |
| 能力单元 | `资格 + 科目 + 大纲节点 + 题型 + 难度` 的可评估学习单元 |
| 学习任务 | 为某一天生成的、具有目标/时长/完成条件/推荐理由的可执行动作 |
| 训练会话 | 用户进入一次题组、案例、论文或复习所创建/恢复的过程记录 |
| 诊断 | 首次或阶段性收集能力证据的短训练流程，不等同于正式模拟 |
| 风险 | 基于证据的分科状态：安全、临界、高风险、数据不足 |
| 复盘 | 用户对错因、正确思路和下次动作的记录 |
| 已发布内容 | 字段完整、审核通过、可参与正式学习计算的内容 |

## 3. 外部约束与假设

1. 系统运行在用户本机，浏览器通过本地后端访问数据。
2. 一名用户在同一时刻使用一个本地数据集；无需设计多用户冲突解决。
3. 用户可导入个人合法持有的学习资料；系统保存来源与审核状态。
4. 目标考试规则会变化，资格、科目、合格线、时长和日期均由配置提供。
5. AI 功能为可选能力；无密钥、网络失败或模型失败时，核心学习流程仍可完成。

## 4. 功能需求

需求优先级：M=本期必须，S=本期应该，C=可选。

### 4.1 设置与资格配置

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-SET-01 | M | 系统应允许用户选择/查看当前资格、目标考试日期、所在时区、每周可用时间和学习日偏好。 |
| FR-SET-02 | M | 未设置考试日期时，系统应允许诊断和训练，但不得显示固定日期倒计时或冲刺结论。 |
| FR-SET-03 | M | 用户修改每周可用时间后，系统应要求或提示重排未开始的未来任务；不得删除完成、进行中或历史任务。 |
| FR-SET-04 | S | 系统应保存用户是否拥有可用于论文的项目经历及其隐私偏好，仅用于推荐，不公开展示。 |
| FR-SET-05 | M | 资格、科目、满分、合格线、建议时长和考试模板均应来自可维护配置。 |

### 4.2 诊断

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-DIA-01 | M | 当无有效诊断且历史证据不足时，系统应在学习总览提示开始诊断。 |
| FR-DIA-02 | M | 诊断应包含基础设置、综合短题组、至少一个案例小问、论文提纲或素材盘点、诊断报告五个阶段。 |
| FR-DIA-03 | M | 系统应在诊断中保存已明确提交的答案、用时、置信度和文本；用户可主动暂存后继续。 |
| FR-DIA-04 | M | 综合诊断提交前不得展示正确答案、解析或累计得分。 |
| FR-DIA-05 | M | 用户可跳过案例或论文诊断，但必须选择或填写跳过原因；系统应将该科标记为数据不足或部分数据。 |
| FR-DIA-06 | M | 诊断完成后，系统应生成三科独立的风险摘要、证据、数据可信度和第一周建议。 |
| FR-DIA-07 | M | 数据不足时，系统不得计算或展示精确分数、通过概率或误导性的风险等级。 |
| FR-DIA-08 | S | 系统应允许用户在生成任务前返回修改基础设置并重新计算建议。 |

### 4.3 学习任务

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-TASK-01 | M | 系统应按本地日期为用户生成当日 1–3 个任务；每个任务必须有类型、关联对象、预计时长、完成条件和推荐理由。 |
| FR-TASK-02 | M | 任务生成优先级应依次考虑：到期复习、高风险科目的高收益薄弱项、三科平衡、用户主动目标。 |
| FR-TASK-03 | M | 默认任务包的预计总时长不得超过用户当天可用时间；超长任务应被拆分、延后或要求用户确认。 |
| FR-TASK-04 | M | 用户应可选择 15/30/60/120 分钟或自定义时长来重排未开始任务；已开始任务保持不变。 |
| FR-TASK-05 | M | 用户开始任务后，系统应创建或恢复对应训练会话，并直接进入预设内容。 |
| FR-TASK-06 | M | 用户应可暂存任务；暂存任务可从总览或对应训练入口继续。 |
| FR-TASK-07 | M | 用户应可跳过未开始任务并记录原因；跳过本身不得改变掌握度。 |
| FR-TASK-08 | M | 当任务到期未处理时，系统应在次日将其标记为过期，并由规则决定继承、替换、拆分或取消；系统不得静默删除。 |
| FR-TASK-09 | M | 当关联内容不足或未发布时，系统不得生成无关替代训练；应显示内容缺口。 |
| FR-TASK-10 | S | 系统应支持用户从总览进入自由练习；自由练习结果应写入能力证据，但不自动等价为任务完成。 |

### 4.4 综合知识训练

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-CHO-01 | M | 系统应支持按任务配置或用户筛选创建综合题组。 |
| FR-CHO-02 | M | 系统应记录每题答案、作答用时、题目顺序、标记状态和可选置信度。 |
| FR-CHO-03 | M | 题组提交后，系统应提供正误、正确答案、解析和关联知识点。 |
| FR-CHO-04 | M | 系统应识别高置信错误、低置信正确和未知置信度；未知不得被推断为任一置信度。 |
| FR-CHO-05 | M | 错题应可进入复盘；用户可填写错因和一句反思。 |
| FR-CHO-06 | M | 题组结果应更新学习记录、能力证据和后续任务候选。 |

### 4.5 案例训练

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-CASE-01 | M | 系统应以案例小问为最小作答、计时和复盘单元。 |
| FR-CASE-02 | M | 小问开始时应显示背景、问题、分值（有则显示）和建议时长。 |
| FR-CASE-03 | M | 用户提交初次作答前，系统不得展示参考评分点或参考答案。 |
| FR-CASE-04 | M | 初次作答提交后，用户应可逐项标记评分点为已覆盖、待补充、不适用或待确认。 |
| FR-CASE-05 | M | 系统应保存初始答案、补充内容、评分点状态、用户复盘和用时。 |
| FR-CASE-06 | S | 系统可提供 AI 评分点建议，但必须与用户自评区分、可编辑且不阻塞保存。 |

### 4.6 论文训练与学习资产

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-ESS-01 | M | 系统应允许用户创建、编辑、归档和检索项目事实卡。 |
| FR-ESS-02 | M | 事实卡至少应支持背景、职责、约束、决策、结果/证据、关联主题和质量属性。 |
| FR-ESS-03 | M | 用户应可基于论文题目和事实卡创建、保存和修改提纲。 |
| FR-ESS-04 | M | 系统应区分论文事实卡、提纲训练、全文写作和全文模拟，不得混淆完成记录。 |
| FR-ESS-05 | S | 系统应支持全文写作的版本保存、字数统计、建议时长和提交复盘。 |
| FR-ESS-06 | C | 系统可向外部 AI 发送用户明确选择的论文内容，返回结构/事实/主题建议；外发前必须告知内容范围。 |

### 4.7 错题与间隔复习

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-REV-01 | M | 系统应将错题、遗漏评分点、高置信错误或用户手动加入项创建为可复习条目。 |
| FR-REV-02 | M | 复习条目应保存来源、关联能力单元、错因、反思、复习次数、下次复习日期和状态。 |
| FR-REV-03 | M | 开始复习时，系统应先展示题干/小问和历史反思，不得直接显示答案或评分点。 |
| FR-REV-04 | M | 用户完成重新作答或表述后，系统应展示反馈并记录本次回忆/作答结果。 |
| FR-REV-05 | M | 系统应基于复习结果更新下次复习时间和复习状态。 |
| FR-REV-06 | M | 对连续失败的复习条目，系统应推荐知识学习、同类练习或评分点训练；不得仅无限重复同一题。 |

### 4.8 风险、能力与周回顾

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-ANA-01 | M | 系统应分别为综合、案例和论文生成风险状态：安全、临界、高风险或数据不足。 |
| FR-ANA-02 | M | 每个风险状态应至少显示一个支持证据，如覆盖度、近期表现、用时、到期复习或模拟记录。 |
| FR-ANA-03 | M | 系统不得使用跨科平均分掩盖任一科的高风险状态。 |
| FR-ANA-04 | M | 系统应按周汇总计划/实际学习时间、任务完成、复习完成、三科变化和下周建议。 |
| FR-ANA-05 | M | 周回顾建议最多输出三条，每条必须能映射到任务类型或明确行动。 |
| FR-ANA-06 | M | 用户修改下周可用时间后，系统应重排未开始任务，并展示保留与延后的原因。 |
| FR-ANA-07 | S | 系统应保存每日/每周能力快照，以支持趋势查看和计划回溯。 |

### 4.9 内容状态、导入与数据安全

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-CONT-01 | M | 题目、案例、论文题目和其他训练材料应具有暂存、待审核、已发布、待核/有争议、归档状态。 |
| FR-CONT-02 | M | 已发布单选至少必须具备题干、选项、答案、解析、题型、科目、来源和一个大纲标签。 |
| FR-CONT-03 | M | 已发布案例至少必须具备背景、小问、参考评分点或参考答案、来源和标签。 |
| FR-CONT-04 | M | 字段不完整、待核或归档内容不得进入诊断、正式模拟、能力计算和自动任务。 |
| FR-CONT-05 | M | 用户可将已发布内容标记为待核；系统应停止将其用于新的核心评估并标记受影响的历史记录。 |
| FR-DATA-01 | M | 系统应提供本地数据库备份，并在备份成功/失败后给出结果。 |
| FR-DATA-02 | M | 系统应提供可读的学习数据导出；导出不应包含 API 密钥。 |
| FR-DATA-03 | S | 系统应在恢复数据前显示覆盖范围与风险，并要求显式确认。 |

## 5. 状态与业务规则

### 5.1 学习任务状态机

| 当前状态 | 触发 | 目标状态 | 规则 |
| --- | --- | --- | --- |
| 草拟 | 通过生成校验 | 已生成 | 内容、时间与理由完整才可展示 |
| 已生成 | 开始 | 进行中 | 创建/恢复训练会话 |
| 已生成 | 跳过 | 已跳过 | 必须保存原因 |
| 已生成 | 当日结束未处理 | 已过期 | 次日进入重排逻辑 |
| 进行中 | 暂存 | 暂存 | 保存可恢复进度 |
| 暂存 | 继续 | 进行中 | 恢复同一会话 |
| 进行中 | 满足完成条件 | 已完成 | 回写学习结果 |
| 已过期 | 重排决定继承 | 已生成 | 保留原始关联与重排原因 |
| 已过期 | 重排决定取消 | 已取消 | 保留历史记录，不删除 |

### 5.2 内容状态机

```text
暂存 → 待审核 → 已发布
              ↘ 待补充 ─┘
已发布 → 待核/有争议 → 已发布 / 归档
暂存、待审核、待核、归档内容均不得参与核心评估
```

### 5.3 风险判定规则（初版）

1. 数据不足优先于任何风险等级：若科目有效近期证据低于配置阈值，显示数据不足。
2. 风险判定应至少接收覆盖度、近期表现、时间能力、复习欠账和模拟表现（存在时）作为输入。
3. 初版可采用可配置、可解释的规则，不要求机器学习或通过概率模型。
4. 任何单科高风险均应使总览显示“存在高风险科目”。
5. 风险等级变化应保留触发证据和时间，以便周回顾解释。

### 5.4 隐私与 AI 规则

1. API 密钥只保存在用户本地受保护配置中，不随导出内容输出。
2. 调用外部 AI 前，系统必须告知将发送的文本类型和目的。
3. 用户可关闭 AI；关闭后练习、自评、评分点、复盘和数据保存正常可用。
4. AI 结果必须标记为建议来源，支持接受、编辑、拒绝；拒绝不影响用户原始作答。

## 6. 数据需求（逻辑级）

| 数据实体 | 最小内容 | 来源/生命周期 |
| --- | --- | --- |
| 个人设置 | 当前资格、日期、时区、可用时间、偏好 | 用户创建/可修改 |
| 资格与科目配置 | 名称、级别、科目、满分、合格线、时长 | 内置/维护 |
| 大纲节点 | 名称、层级、版本、科目关联 | 导入/维护 |
| 训练内容 | 题干、答案/评分点、标签、来源、状态 | 导入→审核→发布 |
| 诊断会话 | 阶段、进度、作答、用时、结论 | 开始→暂存/完成 |
| 学习任务 | 日期、类型、对象、时长、理由、状态、完成证据 | 自动生成/用户操作 |
| 训练会话与作答 | 任务关联、题目、答案、用时、置信度、自评 | 开始→暂存/提交 |
| 复盘/复习条目 | 错因、反思、历史、下次时间、状态 | 训练后创建/持续更新 |
| 项目事实卡与论文提纲 | 内容、主题、质量属性、版本、隐私标记 | 用户创建/归档 |
| 能力/风险快照 | 时间、科目、证据、风险、可信度 | 诊断/训练/周回顾后生成 |

## 7. 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 可用性 | 本地服务正常时，学习总览、任务开始和训练提交的常规反馈应在 2 秒内完成；长文本保存应给出明确保存状态。 |
| NFR-02 | 可靠性 | 训练文本和已明确提交的作答不得因导航、刷新或短暂前端失败而丢失；需支持暂存恢复。 |
| NFR-03 | 数据安全 | 不执行隐式删除或覆盖本地学习数据；结构变更前必须能够备份，恢复必须显式确认。 |
| NFR-04 | 隐私 | 默认不对外传输学习内容；任何外部 AI 请求需用户触发和范围提示。 |
| NFR-05 | 可解释性 | 自动任务、风险变化和重排结果必须可提供人可读理由。 |
| NFR-06 | 可访问性 | 键盘可完成核心操作；风险、进度、错误和按钮不能只通过颜色传达。 |
| NFR-07 | 兼容性 | 首期支持 Windows 本地启动及现代 Chromium 浏览器；窄屏时核心任务和提交操作可用。 |
| NFR-08 | 可维护性 | 资格/科目/考试模板/风险阈值应可配置；业务规则与 UI 文案不应散落硬编码。 |
| NFR-09 | 可审计性 | 内容发布/待核、任务重排、AI 建议接受/拒绝和数据恢复应保留必要时间与来源记录。 |

## 8. 错误与降级要求

| 情况 | 系统行为 |
| --- | --- |
| 本地后端不可用 | 明确提示连接失败、提供重试和启动指引；不将空响应解释为无数据 |
| 内容不足 | 显示缺少何种已发布内容；不生成无关训练 |
| 保存失败 | 明示保存失败并保留输入内容，允许重试；不得伪造成功状态 |
| AI 调用失败 | 保留原始内容，显示可继续自评/评分点复盘，不阻塞主流程 |
| 题目被标记待核 | 不用于新评估；历史结果标识受影响，不删除 |
| 考试日期已过 | 提示更新目标；暂停冲刺倒计时与自动冲刺建议，不删除学习历史 |

## 9. 验收与可追溯性

- FR-DIA-* 对应用户故事 US-P0-02、US-P0-03；
- FR-TASK-* 对应 US-P1-01 至 US-P1-04；
- FR-CHO-*、FR-CASE-*、FR-ESS-*、FR-REV-* 对应 US-P1-05 至 US-P1-08；
- FR-ANA-* 对应 US-P1-09、US-P1-10；
- FR-CONT-* 对应 US-P0-04。

功能验收应至少覆盖正常、数据不足、中断恢复、保存失败、AI 不可用和内容待核六类场景。测试用例可由本文编号直接追踪。
