# 软考备考产品设计探索 v2

> 定位：以系统架构设计师为首个资格的、本地优先的自适应备考工作台。

## 1. 现状判断

现有产品已具备知识库、图谱、刷题、模拟考试、错题、论文、统计和导入的完整界面骨架，适合作为 v2 的承载层。

当前阻碍学习成效的并非再增加页面，而是三个“驱动层”缺失：

1. **内容可信度与覆盖率**：内置 55 个知识点、约 75 道题，不能支撑真题训练、知识点诊断或多轮模拟。
2. **从诊断到行动的闭环**：学习计划目前只生成四条阶段记录；完成状态、每日任务、可执行的题集和完成反馈尚未串联。
3. **三科协同与迁移**：综合知识、案例和论文共用的架构能力没有被显式建模；未来扩展到其他资格会复制页面和数据，而不是复用引擎。

因此，v2 的北极星不是“题目数量”，而是：**考生每天打开系统后，在 30 秒内知道最值得做什么；每次作答后，系统知道下一步怎样提高通过概率。**

## 2. 产品边界与原则

- **首期用户**：备考系统架构设计师、预计在一个考试周期内参考的个人用户。
- **考试优先**：以“当次三科全部达标”为目标，避免只提升单选正确率。
- **本地优先**：题库、作答、论文素材与 AI 配置均可留在本机；导出格式公开、可迁移。
- **人机协作**：AI 只承担批改、归因建议、提纲反馈和内容整理；真题答案、评分点、知识标签需保留人工确认。
- **资格配置化**：资格、科目、考试模板、大纲、能力维度均以数据配置表达，页面与训练引擎不因资格变化而重写。

## 3. 核心学习闭环

```text
首次诊断 / 历史数据
          ↓
能力模型（知识掌握 × 题型能力 × 时间能力 × 遗忘风险）
          ↓
今日 1–3 个可完成任务 ──→ 针对性题集 / 案例拆解 / 论文练笔
          ↓                                    ↓
作答、用时、置信度、错因、反思  ←──────────────┘
          ↓
掌握度与复习队列更新 → 下一日任务与冲刺建议
```

### 3.1 今日页：从“数据看板”改为行动台

页面第一屏只保留一个主按钮：`开始今天的 35 分钟任务`。任务包包含：

- 必做：到期错题复习（间隔复习）；
- 高收益：一个薄弱且高频的知识点微练习；
- 保底：一个跨科迁移动作，例如把案例中的质量属性写成论文素材；
- 可选：模拟/论文，按距离考试天数和可用时间推荐。

每个任务显示预估时间、目标、完成条件和“为什么是它”。完成后即时呈现对能力模型和计划的影响，而非仅显示“已完成”。

### 3.2 首次诊断

首次进入或数据不足时，启动 45–60 分钟自适应诊断：综合知识 20–30 题、案例 1 个小问、论文提纲 1 题。除了正误，采集用时与主观置信度。输出：

- 三科风险灯（安全 / 临界 / 高风险）；
- 知识域掌握热图；
- 推荐每周时间配比；
- 第一周可执行计划。

## 4. 能力模型（产品核心）

以 `能力单元` 取代仅按知识点统计正确率。一个能力单元由：`资格 → 科目 → 大纲知识点 → 题型 → 难度` 构成，并允许题目关联多个单元。

建议的 v2 指标：

| 指标 | 含义 | 用途 |
| --- | --- | --- |
| 掌握度 | 正确率、近期表现、难度、复习稳定度的加权值 | 决定是否进入练习或复习 |
| 置信校准 | “自认为会”与实际结果的偏差 | 识别侥幸正确和盲区 |
| 时间能力 | 单题/小问用时相对目标时长 | 识别会做但做不完 |
| 遗忘风险 | SM-2 到期、最后学习时间、历史波动 | 生成每日复习队列 |
| 通过风险 | 三科分别预测，不以平均分掩盖偏科 | 决定阶段策略 |

初期不必引入黑箱模型。采用可解释的加权规则即可，并在页面展示推荐原因：例如“ATAM：近两次正确率 40%，且 4 天未复习；在近年案例中权重高”。

## 5. 系统架构演进

保留 FastAPI + SQLite + Vue 的本地部署方式，新增以下稳定领域层：

```text
资格配置（Certification / Subject / ExamTemplate / SyllabusVersion）
                    ↓
内容中心（Knowledge / Question / Rubric / Source / ImportReview）
                    ↓
学习引擎（Diagnostic / Mastery / Scheduler / Recommendation）
                    ↓
训练体验（Practice / Mock / CaseWorkshop / EssayStudio / Review）
                    ↓
学习资产（Attempt / Reflection / EssayMaterial / ADR / Export）
```

### 5.1 建议新增实体

- `certifications`：资格名称、级别、有效期、状态；首条为“系统架构设计师”。
- `subjects`：关联资格，定义科目、满分、合格线、时长和考试说明。
- `syllabus_versions` / `syllabus_nodes`：大纲版本化，避免改纲后污染历史数据。
- `question_sources`：真题来源、年份、场次、页码、版权/校验状态；题目不再只用 `source_year`。
- `question_rubrics`：案例/论文评分点，支持人工自评与 AI 辅助逐点反馈。
- `diagnostic_sessions`：诊断快照及结论，便于衡量成长。
- `learning_tasks`：日期、任务类型、关联能力单元、预计分钟、生成理由、完成证据、状态；替换当前仅有的 `study_plans`。
- `mastery_snapshots`：每日能力快照，支持趋势与计划回溯。

### 5.2 兼容与迁移策略

现有 `knowledge_points`、`questions`、`attempts`、`wrong_questions` 保留。先增加可为空的 `certification_id`、`subject_id`、`syllabus_version_id` 并用迁移脚本将当前数据归属到默认资格。这样可逐步上线，不中断既有数据。

## 6. 三科产品体验

### 综合知识：效率与覆盖

- 知识点微练习、年份/章节/难度筛选、限时题组；
- 作答时记录置信度（不确定 / 一般 / 确定），错题复盘时突出“高置信错误”；
- 模拟报告提供知识域、题型和用时的三维拆解。

### 案例分析：评分点与表达

- 以“小问”为最小作答与评分单元，显示分值和建议时间；
- 先自评命中的关键词/评分点，再查看参考答案；
- AI 仅给出“已覆盖 / 可补充 / 不成立”的评分点建议，用户确认后写入记录。

### 论文：素材到成文

- 把素材库升级为可检索的“项目事实卡”：背景、约束、职责、决策、指标、风险、结果、可对应主题；
- 写作前提供选题匹配、提纲检查与材料拼装，写作后提供字数、段落结构、跑题风险与可验证性检查；
- 保存版本与复盘，不将一次 AI 评分作为最终能力结论。

## 7. 内容运营与质量控制

题库是第一优先级。建议建立“导入工作台”，而不只导入 Excel：

1. PDF/Excel/JSON 导入到暂存区；
2. 结构校验：题干、选项、答案、年份、题型、知识标签、评分点；
3. 人工审核并记录来源页码；
4. 去重与冲突提示；
5. 发布到正式题库；
6. 有争议题可标记为“待核”，不参与能力计算。

内容优先顺序：近年综合真题 → 近年案例及评分点 → 论文题目与提纲 → 跨学科共性题。每一题至少绑定一个大纲节点；案例和论文至少有可核对的评分点或提纲。

## 8. 分阶段交付

| 阶段 | 目标 | 可验收结果 |
| --- | --- | --- |
| P0：内容与诊断 | 建立可信内容基线 | 导入审核、真题来源记录、首次诊断与三科风险页 |
| P1：每日闭环 | 让系统每天可用 | 学习任务、完成打卡、推荐理由、复习队列与周回顾 |
| P2：深度训练 | 改善案例与论文表现 | 评分点工作台、案例自评、论文事实卡和版本复盘 |
| P3：资格平台化 | 复用到其他软考 | 资格/大纲/科目配置，选择资格后复用学习引擎 |

## 9. 最小可行版本（建议下一开发切口）

先完成 **“今日任务引擎 + 任务完成闭环”**，不新增复杂 AI：

1. 新建 `learning_tasks`，支持题组练习、错题复习、案例、论文四类任务；
2. 每日按“到期复习 → 高风险薄弱点 → 三科平衡”生成 1–3 个任务；
3. 首页改为行动台，直接进入对应训练；
4. 训练完成自动回写任务、作答数据和下一次推荐；
5. 增加一页周回顾：投入时间、三科风险变化、下周建议。

这条切口能立即利用现有题库、SM-2 与统计能力，也为后续的题库扩充和多资格配置提供稳定入口。

## 10. 待确认的产品决策

- 参考日期与所在省份：考试日期与报考政策应由用户确认后写入配置，不能在代码中固定。
- 现有真题资料的格式、年份范围和可用性：决定 P0 的导入工作量。
- 每周可投入时间、当前基础与是否有项目经历：决定诊断难度与论文素材策略。
- 是否始终坚持本地单机：若后续需要跨设备同步，再增加可选的加密导出/导入，避免过早引入账号体系。
