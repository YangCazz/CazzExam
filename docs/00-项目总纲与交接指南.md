# 软考备考工作台：项目总纲与交接指南

> 用途：本文件是项目的恢复入口与交接入口。新成员或新上下文应先阅读本文件，再按“文档阅读顺序”进入对应资料。
>
> 当前阶段：**产品发现与重构规划**。现有应用可运行，但后续工作应先完成产品需求与产品设计，再进入软件需求和实现。

## 1. 项目一句话

为准备软考的个人用户提供本地优先的备考工作台；首个资格是“系统架构设计师”，核心目标是通过诊断、每日任务、训练、复盘和复习调度，帮助用户实现高级资格三科协同达标，并逐步扩展到其他软考资格。

## 2. 当前状态

- 技术形态：Vue 3 + Vite 前端，FastAPI + SQLAlchemy 后端，SQLite 本地数据库。
- 已有能力：知识库/图谱、题库与导入、练习、模拟考试、错题与 SM-2、学习计划、统计、论文与 AI 网关设置。
- 当前主要缺口：产品需求未完整沉淀；每日任务没有真正形成“生成—执行—回写”的闭环；计划、能力画像和资格扩展仍偏原型；真题内容的规模与审核机制需要加强。
- 本地数据：`backend/data/study.db`，属于用户学习资产，禁止随意删除、覆盖或提交到公开仓库。

## 3. 目录现状与职责

```text
软考/
├─ README.md                 # 项目入口与快速启动说明
├─ start.cmd                 # Windows 一键启动前后端
├─ backend/                  # FastAPI 应用
│  ├─ app/                   # 路由、领域模型、服务、配置、数据库初始化
│  ├─ data/                  # SQLite 数据库与本地备份（用户数据）
│  ├─ scripts/               # 初始化、导入、健康检查、备份等运维脚本
│  └─ tests/                 # API 自动化测试
├─ frontend/                 # Vue 3 前端
│  ├─ src/                   # 页面、组件、路由、接口与样式
│  └─ node_modules/          # 本地依赖，不作为源码维护对象
├─ docs/                     # 产品、设计、使用与交接资料（本文件所在位置）
└─ tools/                    # 内嵌 Python、依赖缓存、临时验证脚本和截图
```

### 3.1 后端模块地图

| 路径 | 职责 |
| --- | --- |
| `backend/app/main.py` | 应用入口、路由注册、CORS、生命周期 |
| `backend/app/models/` | SQLAlchemy 数据模型；按知识、题目、考试、错题、计划、论文分域 |
| `backend/app/routers/` | REST API；与前端功能模块一一对应 |
| `backend/app/services/` | SM-2 复习调度、AI 网关、批改等领域服务 |
| `backend/scripts/` | 数据初始化、PDF/JSON/Excel 导入、备份与健康检查 |

### 3.2 前端模块地图

| 路径 | 职责 |
| --- | --- |
| `frontend/src/App.vue` | 全局布局、导航、页面元信息 |
| `frontend/src/views/` | 总览、知识库、练习、图谱、题库、模拟、错题、计划、统计、论文、设置 |
| `frontend/src/api/client.js` | API 调用封装 |
| `frontend/src/router/index.js` | 前端路由表 |
| `frontend/src/style.css` | 全局视觉样式 |

### 整理规则

1. 不移动 `backend/data/`、`start.cmd`、`frontend/node_modules/`，除非同步更新启动和构建验证。
2. 文档先复制/改名并更新链接，再删除旧副本；历史设计放入 `docs/archive/`，不直接丢弃。
3. `tools/` 中的内嵌运行时、缓存和验证脚本分离；运行时与缓存不作为业务源码修改。
4. 每次目录迁移必须执行启动、后端测试与前端构建，并在本文件的“变更记录”登记。

## 5. 文档阅读顺序与交付链

后续文档必须依序产生，避免“先写数据库、再猜需求”：

```text

        ↓
02 产品设计（用户如何完成目标）
        ↓
03 软件需求（系统必须满足的行为与规则）
        ↓
04 技术设计（如何实现、如何演进、如何验证）
        ↓
05 内容与测试（题库质量、验收、发布）
```

| 层级 | 首份产物 | 需要回答的问题 |
| --- | --- | --- |
| 产品需求 | `PRD-系统架构设计师备考工作台.md` | 用户、场景、痛点、目标、范围、优先级、成功指标 |
| 产品设计 | `核心学习闭环与信息架构.md` | 从首次诊断到每日学习、复盘、冲刺的流程和页面 |

## 6. 启动、验证与关键入口

- Windows 一键启动：双击 `start.cmd`；前端为 `http://127.0.0.1:5173`，后端为 `http://127.0.0.1:8000`。
- 后端健康检查：在项目根目录执行 `tools/python/python.exe backend/scripts/health_check.py`。
- 后端测试：在 `backend/` 执行 `../tools/python/python.exe -m pytest tests`。
- 前端构建：在 `frontend/` 执行 `npm run build`。
- 数据备份：在项目根目录执行 `tools/python/python.exe backend/scripts/backup_db.py`。

## 7. 当前约束与待确认项

- 考试日期、考试形式、科目规则不可在代码中硬编码；以用户配置和当期官方公告为准。
- 真题及解析仅限个人学习用途；导入时须记录来源、年份、场次、页码与审核状态。
- 是否保持纯本地单机、是否需要多设备同步，需在 PRD 中决定；在此之前不引入账号体系。
- AI 输出只能作为建议，案例/论文评分点、错因和题目标签应允许用户确认与修订。

## 8. 新上下文恢复清单

恢复工作时，按以下顺序快速建立上下文：

1. 阅读本文件和根目录 `README.md`。
2. 确认用户当前目标处于产品需求、产品设计、软件需求还是实现阶段。
3. 查看 `docs/` 下对应层级的最新文档及其变更记录。
4. 若涉及代码，检查 `backend/app/main.py`、前端路由和相关页面/API；不要仅凭旧设计文档推断实现现状。
5. 运行健康检查；改动代码后至少运行相关测试与前端构建。
6. 变更数据结构前先备份 `backend/data/study.db`，并提供迁移与回滚方案。

可直接使用的恢复提示词：

> 请阅读 `docs/00-项目总纲与交接指南.md`，确认当前阶段与最近设计文档；先报告现状、风险和下一项最小可验证工作，再进行改动。保持本地数据兼容，不移动或删除文件，除非先提出迁移方案并完成验证。
